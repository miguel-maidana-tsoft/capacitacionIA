Probabilístico vs. determinístico

Una instrucción es una sugerencia.
Un test es una garantía.

El modelo

Razona, interpreta y se adapta a lo nuevo. Puede variar, omitir un paso o equivocarse.

 
Ideal para: entender specs, diseñar, escribir código

El código

Hace siempre exactamente lo mismo. No interpreta, no se olvida, no se cansa.

 
Ideal para: tests, linters, validaciones, bloqueos

Regla de oro: si algo tiene que pasar siempre, no se lo pidas al modelo. Hacelo determinístico.

Alucinaciones

Si no tiene el dato,
inventa algo que suena bien.

respuesta del modelo
// Reembolsar todos los pagos del cliente
import { payments } from '@acme/sdk'

const r = await payments.refundAll({
  customerId, force: true
})
No existeen esta versión de la librería

Qué no funciona

  • Escribir "no inventes" en el prompt
  • Confiar en el tono seguro

Qué sí funciona

  • Darle la fuente real: docs, código, MCP
  • Que compile y corra tests: el error aparece solo
  • Pedirle de dónde sale cada dato
  • Revisión humana en los puntos críticos

Las alucinaciones no se evitan pidiendo: se controlan dando fuentes reales y formas de verificar.

Un archivo en la raíz del repo que el agente lee siempre, antes de cualquier tarea. En Claude Code: CLAUDE.md.

spec.md
  1. Qué se construyeEn 2–5 oraciones, sin jerga interna.
  2. ActoresQuién lo usa, quién lo dispara, qué sistemas intervienen.

Model Context Protocol

Una skill le enseña cómo.
Un MCP le da la capacidad.

Un estándar abierto. Cada servidor MCP expone herramientas —leer un ticket, correr una colección, abrir una página— que cualquier agente compatible puede usar.

$ codex mcp add chrome-devtools \
    npx chrome-devtools-mcp@latest

El riesgo de conectar · prompt injection

Todo lo que lee es
potencialmente una orden.

El agente no distingue bien entre tus instrucciones y el texto que lee. Un ticket, un README o una web pueden traer instrucciones escondidas.

Cada MCP con el mínimo acceso necesario
Nunca acceso a secretos ni credenciales
Aprobación humana para acciones irreversibles
Todo contenido externo es no confiable

Lo más valioso que le podés dar a un agente es una forma de saber si lo hizo bien.

Hooks

Garantías que no dependen del modelo.

Un hook ejecuta una acción automáticamente cuando ocurre un evento. No depende de que el modelo "se acuerde".

EventoAntes de ejecutar un comando
rm -rf · push directo a mainBLOQUEADO
EventoDespués de editar un archivo
Corre el formateador del proyectoOK
EventoAl terminar la tarea
Lint + tests, y reporta el resultadoOK
En AGENTS.md: "siempre formateá"
puede olvidarse
Como hook
siempre, sin excepción

Las reglas que "nunca se rompen" no se escriben en un prompt: se implementan como hook.
